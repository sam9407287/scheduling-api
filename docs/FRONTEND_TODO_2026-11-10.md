# 前端交辦（2026-11-10）— PM 回報「PM Test 機構無法新增員工」「到職日沒辦法輸入年月日」

PM 在新機構「PM Test」新增員工（員工編號 `1`、到職日顯示 `0110/01/01`）得到
`employee_id: 這個 員工編號 在 員工 已經存在。`。拆成兩件事：一件後端已修、一件要前端改。

## 1. 後端已修（前端不用改）：員工編號改為「機構內唯一」

- 原本 `Employee.employee_id` 是**全系統**唯一，別的機構用過 `1`，新機構就不能再用。
- 現在改為 `(organization, employee_id)` 唯一（migration `employees.0006`）。不同機構可以各自有編號 `1`。
- 同機構重複時仍回 `400`，欄位一樣掛在 `employee_id`，訊息改為
  `這個員工編號在此機構已經存在。`（`parseApiErrorMessage` 現有邏輯可直接顯示）。
- API 形狀沒有變。

## 2. 要改：到職日欄位（`EmployeeFormDialog.tsx`）

現況：`<Input type="date" ... required />` 放在「契約類型／薪制／週工時／到職日」四欄並排的最後一格。

問題：

1. **欄位太窄**。四欄並排時日期欄只夠顯示 `0110/01/01`，右側的日曆圖示被擠掉，
   使用者點不到日曆、也看不出年／月／日是分段輸入的 → PM 的說法是「沒辦法輸入年月日」。
2. **打民國年不會被擋**。原生 date input 的年份欄打 `110` 會變成西元 `0110` 年並照樣送出。
   台灣使用者很習慣打民國年。

建議：

- 到職日獨立一列，或把這一排改成兩欄 × 兩列，讓日期欄至少有約 180px、日曆圖示看得到。
- 加上範圍：`min="1950-01-01"`、`max` 設為今天往後一年左右，瀏覽器就會擋掉 `0110`。
- 標籤旁加提示「西元年，例如 2021/01/01」。若想支援民國年輸入，可在 `onChange`／送出前
  把年份 < 1911 的值自動加 1911（`0110-01-01` → `2021-01-01`）並讓使用者看到換算結果；
  要不要做由前端判斷。

後端防線（已上）：`hire_date` 早於 `1950-01-01` 一律回 `400`：

```json
{ "hire_date": ["到職日年份請輸入西元年（例如 2021），不是民國年。"] }
```

## 3. 提醒：`user.username`、`user.email` 仍是全系統唯一

登入帳號與 Email 是登入識別，必須全系統唯一，這點沒有變。測試時用 `1` 這種很短的帳號，
很容易跟別的機構撞到，會回：

```json
{ "user": { "username": "A user with this username already exists." } }
```

目前使用者只有管理者、員工不登入系統，所以「帳號／密碼」對員工來說其實用不到。
是否要讓後端在沒填帳號時自動產生（例如 `機構代碼-員工編號`），等產品決定後再排；
前端現階段照舊送 `user.username`。
