## 0. 先把法律講清楚（文案要用對）

勞基法 §36「一例一休」= 每 7 天要有 **2 天休息**，但兩天性質不同：

| | 例假 | 休息日 |
|---|---|---|
| 可不可以出勤 | **不可以**（天災事變才例外） | 可以，但要**員工同意**＋加班費 |
| 所以每週最多上 | 6 天是法律上限 | 5 天是「不用加班費」的正常狀態 |

因此**沒有「一例一休可不可以接受」這種設定**——例假員工同意也不能免除。
真正能問員工的是：**「願不願意上休息日（第 6 天）？」** 這就是 `rest_day_work_ok`。
文案請用「休息日」「第 6 天」「需加班費」，不要寫「同意不休一例一休」。

國定假日則是意願問題：有人想賺假日加給、有人家裡有事不能排。四選一 `holiday_work`。

## 1. 員工設定頁：新增「排班意願」區塊

位置：員工詳情 → 可用性 / 偏好（現在放 `required_hours_per_week`、時段、特殊規則的那一頁），
走既有 `PUT /api/employees/employees/{id}/availability/`，多兩個欄位即可。

建議版面（一張卡片、兩個控制項，不要做成表格）：

```
┌ 排班意願 ──────────────────────────────────────────────┐
│                                                         │
│  休息日出勤                                              │
│  ☐ 願意在人力不足時上「休息日」（每週第 6 天，需加班費）     │
│     ⓘ 例假（每週 1 天）依法不可出勤，此選項不影響例假。       │
│                                                         │
│  國定假日排班                                            │
│  ( ) 不可排         — AI 絕不排、手動排會標紅               │
│  (•) 可排（預設）                                         │
│  ( ) 偏好排假日班   — 假日要人時優先排他                    │
│  ( ) 不優先         — 盡量不排，沒人時仍會排                 │
│                                                         │
└─────────────────────────────────────────────────────────┘
```

要點：
- `rest_day_work_ok` 用 **checkbox / switch**，預設關。旁邊一定要有 ⓘ 說明「例假不受影響」，否則使用者會以為勾了就能排 7 天。
- `holiday_work` 用 **radio 四選一**，每個選項右側一句後果說明（上面那四句），讓管理者知道「不優先 ≠ 不可以」。
- 兩個欄位和既有可用性欄位一起 PUT；不要另開 API。
- 時薪制員工（`pay_type: hourly`）的卡片可加一行灰字：「時薪制假日出勤直接加倍計薪，不套用補休配額」，呼應 §8 加給邏輯。

## 2. 員工列表：兩個小徽章

列表 API 已多回 `scheduling_prefs`，不用逐人打 availability。建議在姓名後面加徽章：

| 條件 | 徽章 | 樣式 |
|---|---|---|
| `rest_day_work_ok: true` | 「可上第 6 天」 | 藍色 outline |
| `holiday_work: forbid` | 「假日不排」 | 紅色 outline |
| `holiday_work: prefer` | 「偏好假日」 | 綠色 outline |
| `holiday_work: avoid` | 「假日不優先」 | 灰色 outline |
| `allow` / 預設 | 不顯示 | — |

列表篩選器可加「假日意願」下拉（四選一），排假日班時管理者會想先看誰願意。

## 3. 排班頁：選完期間先顯示「這段要休幾天」

這是使用者最有感的一塊。選完 `period_start / period_end` 後（按 AI 排班**之前**）打
`GET /api/ai/schedule/rest-quota/`，在期間選擇器下方顯示一條摘要列：

```
10/1 – 10/30 共 30 天 ｜ 週休 9 天 ＋ 國定假日 4 天（國慶日、國慶日補假、光復節、光復節補假）
→ 月薪制員工最多上 17 天        [查看每人配額 ▾]
```

- 國定假日名稱 hover 或展開顯示；`kind: makeup` 文案是「補假日」（放假），不是補班日（見 10/26 待辦）。
- 「查看每人配額」展開一張小表：姓名、薪制、`work_days_max`（時薪制顯示「—」）、休息日同意、假日意願。
  這張表就是管理者排班前的「盤點」，讓他知道哪些人假日不能用、誰可以多上一天。
- 這支免費、不計費、很快（不跑 solver），可以在期間一變就自動重打，不用按鈕。
- 沒有國定假日的期間就只顯示週休，不要出現「國定假日 0 天」這種贅字。

### 3.1 AI 排班結果：顯示排休摘要與超配額

`POST /api/ai/schedule/generate/` 回來的 `metadata.rest_quota.employees[]` 每人一列：
`work_days / rest_days / holiday_days_worked / over_quota`。建議在結果對話框或班表右側面板：

- `over_quota > 0` 的人標黃，文案「超過排休配額 N 天（人力不足時 AI 平均分攤）」。
  這不是違法，是提醒管理者「這個月人不夠」，可以考慮調人力需求或找兼職。
- `holiday_days_worked > 0` 的人顯示「假日上班 N 天，已在其他天補休」——這句話是月薪制「補休原則」的使用者版解釋。
- `applies: false`（時薪制）不顯示配額欄位。

派生合規版（`/derive-legal/`）的 `rest_quota` 是 `null`，因為合規版只守法律最低限度、不做排休，不要在那邊顯示配額。

## 4. 班表格子與合規檢查：兩個新的視覺狀態

### 4.1 國定假日欄

班表上國定假日那一欄本來就有假日底色（10/22 待辦）。現在加上：
- 拖人進假日格時，如果該員工 `holiday_work: forbid`，**拖放時就阻擋**並 toast「王小明 設定不可排國定假日」。
  後端不擋手動排班（警告哲學），但這種設定錯誤讓使用者拖完才看到紅框體驗很差，前端先擋。
- `prefer` 的員工在假日欄的名字旁可放一個小 ★，表示「他想上這天」。

### 4.2 合規檢查新規則

`check-compliance` 多一種 `rule: "holiday_work_refused"`，`severity: hard`（紅框），
`rule_label` 已是中文「員工設定不可排國定假日卻被排班」。和其他 hard 規則同樣渲染即可。
既有 `holiday_scheduling`（soft、黃）的 `detail` 多了 `holiday_work`，tooltip 可以寫成
「國定假日出勤（該員工：不優先）— 工資應加倍／補休」。

### 4.3 一例一休提示文案微調

`weekly_rest_days` soft（上 6 天）的黃色提示，現在應該區分：
- 員工 `rest_day_work_ok: true` → 「休息日出勤（員工已同意），需加班費」
- `false` → 「休息日出勤（**員工未同意**），需取得同意並給加班費」

前端拿 `scheduling_prefs.rest_day_work_ok` 判斷即可，後端這條規則本身沒變。

## 5. AI 排班對話框：不用新增選項

這次所有行為都由員工設定和期間自動帶入，**不需要**在 AI 排班對話框加新 checkbox。
唯一建議加的是對話框頂部重複顯示 §3 那條摘要列，讓使用者按下去之前再確認一次人力盤點。
