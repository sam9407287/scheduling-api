## 2. 要改：手機寬度下到職日欄位比左邊低一截

390px 寬時標籤「到職日 西元年，例如 2021/01/01」折成兩行，到職日輸入框比同一列的「週工時」低約一行。

## 3. 建議改：只把「像民國年」的年份拿來換算

現在年份 `1`–`1910` 都會加 1911。打 `1900`（手滑）會顯示「已將民國 1900 年換算為西元 3811/06/01，請確認」，
之後才被 `max` 擋下，訊息很怪。建議把條件縮到民國年合理範圍，例如 `year >= 1 && year <= 150`；
其餘交給 `min`／`max` 與後端（早於 1950-01-01 回 400）去擋。

## 4. 知道就好：民國閏年的 2/29 打不進去

打民國 `113/02/29`（＝2024/02/29）時，原生 date input 把它當成西元 0113 年，那一年不是閏年，
欄位值直接變成空字串，也就不會觸發換算。使用者改打西元 `2024/02/29` 可以正常輸入。
發生機率很低，除非改用自訂的日期輸入元件，否則不用特別處理。

## 5. 後端已改（前端不用改）

這兩項已在後端分支 `fix/employee-natural-order`，**尚未部署**；部署前線上行為照舊。

- **新增員工沒帶 `organization` 時，自動用操作者的機構。** 表單上的「機構（選填）」原本其實是必填
  （沒選會回 `400 organization: 此為必需欄位。`）；部署後不選也能建立。操作者自己沒有機構時仍回
  `400 {"organization": ["請選擇機構。"]}`。有帶 `organization` 時行為不變。

  會在 console 看到），部署後就不會了。瀏覽器本來就會丟掉 204 的 body，所以線上的資料內容沒有差別。
