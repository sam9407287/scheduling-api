# 前端交辦（2026-11-16）— 「違規提醒」改版：分類聚合＋直接在班表上看

PM 回饋：合規檢查一次回幾百筆，逐筆攤開很難處理。希望（1）先看重點、依類型聚合；
（2）直接在排班表上看到哪些班次有違規、有提醒。

Android／iOS 已照下面的規格完成並實測，**網頁版請做成一樣的行為與文案**。
後端不用改：全部用現有的 `POST /api/schedules/versions/{id}/check-compliance/` 回傳。

## 1. 合規檢查結果面板

由上到下四塊：

1. **三個數字**（點了切到對應分頁）
   - 人力不足班次：`coverage` 中 `status == "under"` 的筆數
   - 合規違規：硬性違規筆數
   - 注意提醒：軟性提醒筆數
   - 數字為 0 時顯示綠色與「沒有問題」。
2. **問題類型分布**：一條橫向色條，每個分類一段，寬度依筆數（最小 2%，少量的分類才看得到）。
   違規用紅色系、提醒用琥珀色系、人力用灰藍色系，同性質內由深到淺。
3. **分頁**：全部／違規／提醒／人力，各帶筆數。有違規時預設停在「違規」。
4. **分類清單**（預設全部收合，一次只展開一個）
   - 收合：`● 分類名稱　　N 筆  ˅`
   - 展開：這類問題的**說明**、**智慧修正方向**、底下列出各筆（`員工 · 日期`＋一行內容，含數字）。
   - 每個分類最多列 30 筆，超過顯示「還有 N 筆沒有列出；到班表用『僅看違規／提醒』逐週處理會比較快」。
   - 點任一筆 → 關閉面板、跳到那一週，並把班表篩選切成該性質（違規／提醒）。
   - 底部按鈕：「關閉」「在班表上查看」（跳到第一筆違規所在的那一週，沒有違規就第一筆提醒）。

### 怎麼分類

- 違規／提醒：以 `(rule, 是否軟性)` 分組。軟性判斷：`violation.severity == "soft"` **或** `rule` 在回傳的 `soft_rule_types` 裡。
  同一條規則可能同時有硬性與軟性（例如一例一休），分成兩類。
- 人力（來自 `coverage`）分三類：
  - 人力不足：`status == "under"` —「已排 {assigned} / 需要 {required_min} 人」
  - 超過人數上限：`status == "over"` 且 `source != "unplanned"` —「已排 {assigned} 人，超過上限 {required_max}」
  - 未開班卻有人排班：`source == "unplanned"` —「計畫沒開這個班，卻排了 {assigned} 人」
- 排序：違規 → 提醒 → 人力；同性質內筆數多的在前。

### 各規則的名稱、說明、修正方向（請用同一套文案）

| `rule` | 分類名稱 | 說明 | 智慧修正方向 |
|---|---|---|---|
| `max_daily_hours` | 每日工時超限 | 單一班次的工時超過系統設定的每日上限，需核對是否適用法令例外。 | 評估拆分班次或調整工作時間，確保單日工時符合適用規則。 |
| `max_daily_total_hours` | 每日總工時超限 | 同一天多個班次合計的工時超過每日上限。 | 把同一天的其中一班改給其他同事，或改排較短的班別。 |
| `min_rest_hours` | 班次休息間隔不足 | 相鄰兩個班次之間的休息時間低於設定的最低時數。 | 把後一班改成較晚開始的班別，或換給休息時間足夠的同事。 |
| `max_weekly_hours` | 每週工時超限 | 當週排定的總工時超過每週上限。 | 把該週其中一班改給工時還有餘裕的同事，或改排較短的班別。 |
| `max_consecutive_days` | 連續出勤天數超限 | 連續出勤的天數超過設定上限。 | 在連續出勤的中間安排一天休息，由其他同事補上那一班。 |
| `weekly_rest_days` | 一例一休（每七日休息日） | 每七天要有例假與休息日：例假不可出勤，休息日出勤需員工同意並給加班費。 | 把這天改為休假；若屬休息日出勤，請先取得員工同意並確認加班費。 |
| `holiday_scheduling` | 國定假日出勤 | 排在國定假日的班次，工資應加倍或安排補休。 | 確認加倍工資或補休安排；也可以改排偏好假日班的同事。 |
| `holiday_work_refused` | 員工不可排國定假日 | 員工的排班意願設定為「不可排國定假日」，卻被排了假日班。 | 改派其他同事；若員工其實願意，先到員工資料調整他的假日意願。 |
| `org_closed_day` | 機構公休日排班 | 班次排在機構設定的每週固定公休日。 | 確認當天是否真的需要開班；不需要就移除這個班次。 |
| `female_night_shift` | 女性夜間工作 | 女性員工排在夜間時段，需符合法令要求的同意與配套。 | 確認已取得同意並提供必要配套，或改排其他時段。 |
| `max_monthly_overtime_hours` | 每月加班時數超限 | 當月累計的加班時數超過設定上限。 | 把後續的加班班次改給加班時數較少的同事。 |
| `min_break_minutes` | 班次中間休息不足 | 班次時間較長，但班別設定的中間休息時間低於規定。 | 到「系統設定 → 班別模板」調高這個班別的休息分鐘數。 |
| 其他 | 沿用後端 `rule_label` | 班次不符合排班規則的設定。 | 檢查這個班次與相鄰班次，調整時間或人員。 |

人力三類的說明／修正方向：

| 分類 | 說明 | 智慧修正方向 |
|---|---|---|
| 人力不足 | 已排人數低於每日班別計畫設定的需求人數。 | 指派工時還有餘裕的同事，或用 AI 排班補齊缺口。 |
| 超過人數上限 | 已排人數超過每日班別計畫設定的上限。 | 把多出來的人移到人力不足的班次，或調高這個班的上限。 |
| 未開班卻有人排班 | 每日班別計畫沒有開這個班，卻有人被排進來。 | 到「每日班別」把這個班加進當天的計畫，或把人移到有開的班。 |

### 每一筆要帶的數字（來自 `violation.detail`）

原本的一行文案（一例一休依員工是否同意、假日出勤帶員工意願等，現有邏輯不變）後面加括號：

| `rule` | 用到的 `detail` 欄位 | 顯示 |
|---|---|---|
| `max_weekly_hours` | `total_hours`, `max_hours` | 本週排定 42 小時，上限 40 小時 |
| `max_daily_hours`／`max_daily_total_hours` | `total_hours`, `max_hours` | 當日 10 小時，上限 8 小時 |
| `min_rest_hours` | `rest_hours`, `required_hours` | 與前一班只隔 8 小時，至少要 11 小時 |
| `max_consecutive_days` | `consecutive_days`, `max_days` | 連續出勤 7 天，上限 6 天 |
| `weekly_rest_days` | `worked_days`, `rest_days` | 這週上班 6 天、休息 1 天 |
| `max_monthly_overtime_hours` | `overtime_hours`, `max_overtime_hours` | 本月加班 50 小時，上限 46 小時 |
| `min_break_minutes` | `break_minutes`, `required_break_minutes` | 休息 30 分鐘，至少要 60 分鐘 |

數字是整數時不要顯示 `.0`。欄位缺少就不加括號。

## 2. 直接在排班表上看

1. **篩選列**（週表頭下方）：`全部班次`／`僅看違規 N`／`僅看提醒 N`，N 是本週符合的班次數。
   - 本週沒有任何有問題的班次時整列不顯示。
   - 選了「僅看違規」：沒有違規的班次淡化（透明度約 0.28），「僅看提醒」同理。
2. **班次卡徽章**：右上角 `!N`，N 是這個班次的問題數；有違規用紅色、只有提醒用琥珀色。
   卡片底色沿用現在的規則（違規紅、提醒琥珀）。
3. **一格可以有多筆違規**。請用 `(employee_pk, schedule_date, shift_template_id)` **分組成陣列**，
   不要用 `Map.set` 之類讓後面的蓋掉前面的。
4. 班次卡上的問題來源（都要算進 N）：
   - 硬性：合規違規、單日工時超過上限、同日班次時間重疊
   - 軟性：合規提醒、跨版本重疊、請假日排班、未開班（每日班別沒有開這個班）

## 3. 班次合規診斷（點有徽章的班次）

在班次詳情裡加一個區塊「班次合規診斷」，右邊顯示「違規 N」「提醒 N」，底下每則問題一張卡片（違規紅底、提醒琥珀底）：

- **標題**：上表的分類名稱（即時警示用「單日工時超限」「同日班次時間重疊」「跨版本重疊」「請假日排班」「未開班」）
- **內容**：同面板那一行（含數字）
- **關聯班次**：`violation.related_dates` 扣掉本身那一天，每個日期一顆可點的小按鈕（`6/1 週一`），點了跳到那一週
- **建議處理方式**：同上表的修正方向
