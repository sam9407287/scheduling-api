## 2. MVP 範圍界定（我的建議，待你拍板）

> 產品概念澄清（2026-07-10，已寫入 CLAUDE.md）：使用者操作的是**一張工作班表**，上面有「人工排（拖拉/改/合規檢查/匯出 Excel）」「AI 自動排」「一鍵生成合規版（可匯出 Excel 對照）」三種能力。A/B 只是解釋用語，非兩個要並存管理的版本。**Excel 匯出在工作班表與派生的合規版都要有。**

以「長照機構實際上線最低需求」為準，把 §13 分成三層：

### 🔴 Must — MVP 必備（不做上不了線）
| # | 功能 | 為什麼是 MVP | 對應 |
|---|---|---|---|
| M1 | **部署上線**（Railway 生產 + Postgres + 真 Email + 生產 Auth + 備份/監控）| 「部署完成」是本目標核心 | 12.x / ADR-0001 |
| M2 | **請假管理**（LeaveRequest + 審核 + 連動可用性/排班）| 長照天天有人請假，無此功能無法運作 | §13.1 |
| M3 | **發布時自動合規檢查**（班表 approve 前自動跑一次）| 避免違法班表被送出 | §13.15 / §9.1 |
| M4 | **班表匯出 Excel**（工作班表 + 合規版兩者）| 客戶要印班表、交接、拿合規版去對照勞檢 | §13.8 |
| M5 | **每日工時 8h / 每週休息 1 天強制** | 勞基法硬底線，客戶會問 | §13.2–13.3 |

### 🟡 Should — 有時間就進，否則首版後補
| # | 功能 | 對應 |
|---|---|---|
| S1 | 加班費自動計算 + 加班上限檢查 + 國定假日表 | §13.4–13.6 |
| S2 | 基本報表（出勤/工時彙總）| §13.8 |
| S3 | 拒絕並退回的審核流程 | §13.14 |

### 🟢 Won't（MVP 明確不做，Phase 4）
Stripe 真扣款（保留 mock）· 勞動法 RAG · 跨機構排班 · i18n · GPS 打卡 · 證照提醒 · 班別變體 · 可用性多時段 · 薪資連動。

> 背景：前端 Frank 本週已 push `0709 table drag`（移動/交換）；後端今天已修 `Schedule` 分頁確定性排序（`0003`），解決拖拉時「班格顯示消失、寫入撞 400」的根因。本週把剩餘的拖拉邊界收乾淨。

### 5.1 後端拖拉支援（Day 1–4）— 本週重頭戲

- [ ] **移動班格**：確認單格 PATCH（改 employee/date/shift）在 serializer 可寫入修正後正常（本 session 已修 serializer）
- [ ] **拖拉後即時合規回饋**：確認 `check-compliance/` 逐格違規能被前端在拖放後即時呼叫並標紅
- [ ] （選）**拖拉前影響評估**：`ai_engine` 的 `evaluate_change` 端點是否要接進拖拉 UX（放下前預覽影響）
