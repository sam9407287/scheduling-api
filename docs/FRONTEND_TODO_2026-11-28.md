# 前端交辦（2026-11-28）— 出勤／異常／加班的機構隔離

後端這次是資安修正，網頁與 App 現有流程**不用改就能繼續用**。下面只有一項文案建議。

## 後端改了什麼

- 出勤、異常紀錄、加班紀錄、加班規則：只回、只接受操作者自己機構的資料（superuser 除外）。
  別的機構的 id 回 `404`；寫入時引用別機構的員工／出勤／分店／機構回 `400`，錯誤掛在該欄位。
- 還沒建立機構的帳號，這幾個清單會是空的（以前會看到全部機構的資料）。
- `POST /api/overtime/records/calculate/`：同一筆出勤重複呼叫不再多產生一筆。
  第一次 `201`＋新紀錄；之後 `200`＋既有紀錄（管理者調過的倍率／備註原樣保留）。

契約細節在 [`FRONTEND_API.md`](./FRONTEND_API.md) §8。

## 建議改（不擋使用）：重複計算時的提示文案

`useCalculateOvertime` 的 `onSuccess` 現在不管 `201` 或 `200` 都顯示「已產生 N 筆加班紀錄」。
狀態碼是 `200` 時代表紀錄本來就在，建議改顯示「這筆出勤已經計算過，沿用既有的 N 筆加班紀錄」。
要拿狀態碼的話 `overtimeApi.calculate` 得回傳 `response.status`（現在只回 `response.data`）。

Android／iOS 的加班頁若有同樣的提示，一併調整。

## 已知限制

出勤的上下班時間事後被改掉時，已經算出來的加班紀錄不會自動跟著更新（再按一次計算也只會拿回舊紀錄）。
目前沒有「重新計算」的入口；需要的話再跟後端說。
